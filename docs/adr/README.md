# Architecture decision records

One file per decision that shaped the architecture and that someone might later ask "why?" about. A record is written once and not rewritten: if the decision changes, a new record supersedes it and the old one's status says so.

Each record has: status, date, who decided, the requirements it serves, the context, the decision, the alternatives considered with why each was rejected, the consequences (positive and the accepted negatives), and what would change the decision.

Smaller day-to-day decisions are not recorded here; they live in the design notes (`docs/design/`) of the tickets that made them.
